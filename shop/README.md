# 🛒 سیم‌شاپ — فروشگاه اینترنتی شماره سیم‌کارت، مودم و کد فعال‌سازی

فروشگاه اینترنتی کاملاً فارسی و راست‌چین (RTL) با پنل نمایندگان و پنل مدیریت حرفه‌ای،
متصل به درگاه‌های پرداخت ایرانی و سرویس پیامک ایرانی.

> **وضعیت:** پیاده‌سازی کامل و اجراشده روی PostgreSQL واقعی.
> ۱۰۰ تست (۸۵ یونیت + ۲ کامپوننت با jsdom + ۱۳ یکپارچه با دیتابیس واقعی) و بیلد production با موفقیت اجرا شده است.

## ویژگی‌ها

### 🧩 محصولات
| نوع محصول | مشخصات | منطق فروش |
|---|---|---|
| **شماره سیم‌کارت** | اپراتور، شماره، قیمت، وضعیت، نماینده، تاریخ، توضیحات | تشخیص خودکار اپراتور از پیش‌شماره + تحلیل خودکار «رند/متوالی/تکراری/آینه» و امتیاز زیبایی |
| **مودم** | برند، مدل، قیمت، موجودی، تصویر، گارانتی، توضیحات | کاهش خودکار موجودی؛ در صفر شدن، از فروشگاه مخفی می‌شود |
| **کد فعال‌سازی** | قیمت **پله‌ای** به تفکیک اپراتور | مشتری فقط اپراتور و تعداد را انتخاب می‌کند؛ قیمت خودکار محاسبه و به درگاه وصل می‌شود |

### 🔒 جلوگیری از فروش همزمان
هنگام رفتن به درگاه پرداخت، شماره به‌صورت **رزرو موقت** (پیش‌فرض ۱۵ دقیقه) قفل می‌شود
با به‌روزرسانی شرطی و اتمی:

```ts
tx.phoneNumber.updateMany({
  where: { id, OR: [{ status: 'AVAILABLE' }, { status: 'RESERVED', reservedUntil: { lt: new Date() } }] },
  data: { status: 'RESERVED', reservedUntil, reservedByToken: orderId },
});
```

اگر پرداخت ناتمام بماند، سفارش منقضی و رزرو آزاد می‌شود.
پس از پرداخت موفق: شماره «فروخته‌شده» شده و از تمام کوئری‌های فروشگاه حذف می‌گردد.

### 🔎 فیلترهای پیشرفته‌ی شماره
اپراتور، بازه قیمت، پیش‌شماره، پسوند، **الگوی عددی خاص** (`*` و `?`)، رند، متوالی، تکراری،
آینه، تعداد ارقام، جستجوی سریع، مرتب‌سازی (ارزان‌ترین/گران‌ترین/جدیدترین/محبوب‌ترین/رندترین)،
صفحه‌بندی + بارگذاری تدریجی (Infinite Scroll) و نمایش فقط شماره‌های موجود.
جزئیات: [`docs/13-filters.md`](docs/13-filters.md)

### 👤 نقش‌ها
| نقش | دسترسی |
|---|---|
| **مهمان** | مرور، فیلتر، خرید (بدون الزام ثبت‌نام)، پیگیری با کد رهگیری |
| **مشتری** | سفارش‌ها، کد ملی برای کد فعال‌سازی |
| **نماینده** | ثبت دستی/گروهی (اکسل) شماره و مودم، گزارش فروش، درخواست تسویه |
| **ادمین** | محصولات، سفارش‌ها، نمایندگان، گزارش‌ها، پیامک، تنظیمات، لاگ |
| **مدیر کل** | همه‌چیز + مدیریت کاربران، نقش‌ها و تنظیمات حساس |

### 🛡️ امنیت
bcrypt (هزینه ۱۲) · JWT امضاشده در کوکی `httpOnly` + `tokenVersion` برای باطل‌سازی فوری ·
RBAC دوسطحی (نقش + دسترسی) · دو مرحله‌ای TOTP برای ادمین · double-submit CSRF + بررسی Origin ·
محدودیت نرخ چندلایه (اپلیکیشن + Nginx) · Zod برای همه‌ی ورودی‌ها · Prisma (بدون SQL دستی؛
کوئری‌های خام پارامتری) · Audit Log کامل با ماسک‌کردن داده‌ی حساس · قفل حساب پس از تلاش‌های ناموفق ·
هدرهای امنیتی + HSTS.

## استک فنی و دلیل انتخاب

| لایه | انتخاب | دلیل |
|---|---|---|
| فرانت‌اند | **Next.js 14 (App Router) + TypeScript** | رندر سمت سرور برای SEO (مهم برای صفحات محصول)، Server Components، یک برنامه برای فرانت و بک |
| بک‌اند | **Next.js Route Handlers** | حذف سرویس جداگانه و کاهش هزینه‌ی نگهداری؛ همان زبان و همان تایپ‌ها |
| دیتابیس | **PostgreSQL 16 + Prisma ORM** | تراکنش واقعی (لازم برای رزرو اتمی و فروش اتمی)، `BigInt`، `text[]`، ایندکس ترکیبی، type-safety کامل |
| کش / Rate Limit | **Redis 7 (ioredis) با fallback حافظه‌ای** | در تک‌سرور بدون Redis هم کار می‌کند؛ در مقیاس، محدودیت نرخ توزیع‌شده |
| UI | **Tailwind CSS + Radix UI + shadcn-style** | RTL کامل، حالت تاریک/روشن، دسترسی‌پذیری (a11y) روی پایه‌ی Radix، فونت وزیرمتن self-hosted |
| اعتبارسنجی | **Zod** | یک اسکیما هم برای اعتبارسنجی و هم برای استنتاج تایپ |
| پرداخت | **زرین‌پال / آیدی‌پی / نکست‌پی** | پوشش متعدد با یک اینترفیس؛ سوییچ از پنل ادمین |
| پیامک | **کاوه‌نگار / ملی‌پیامک** | دو سرویس محبوب ایرانی با اینترفیس یکسان |
| اکسل | **ExcelJS** | ساخت قالب، خواندن سلول‌های فرمول/متن غنی و اعتبارسنجی سطربه‌سطر |
| تست | **Vitest** | سریع، سازگار با TypeScript و ESM |
| استقرار | **Docker + Nginx + certbot + CI/CD** | بازتولیدپذیر، SSL خودکار، بکاپ خودکار، تست در هر push |

### چرا `BigInt` برای مبلغ؟
واحد پول **تومان** است و شماره‌های رند یا سفارش‌های عمده می‌توانند از سقف `Int32`
(~۲٫۱ میلیارد) عبور کنند. `BigInt` سرریز و خطای اعشاری شناور را حذف می‌کند و
تبدیل به رشته در پاسخ‌های JSON به‌صورت متمرکز انجام می‌شود.

### چرا bcrypt و نه Argon2؟
آرگون۲ به کامپایل native نیاز دارد که روی بعضی سرورهای ایرانی/کانتینرهای بدون toolchain
شکست می‌خورد. bcrypt با هزینه‌ی ۱۲ در این مقیاس امن و کاملاً قابل‌حمل است.
(با تنظیم `BCRYPT_COST` بدون تغییر کد قابل ارتقا است.)

## شروع سریع (توسعه)

```bash
# ۱) پیش‌نیاز: Node.js 20+ و PostgreSQL 16 (یا Docker)
cp .env.example .env          # و مقادیر را پر کنید

# ۲) نصب وابستگی‌ها
npm ci

# ۳) ساخت جداول
npx prisma migrate deploy      # روی دیتابیس خالی
# یا برای توسعه:  npx prisma migrate dev

# ۴) داده‌ی اولیه (نقش‌ها، اپراتورها، قیمت‌ها، کاربر نمونه)
npm run db:seed

# ۵) اجرا
npm run dev                    # http://localhost:3000
```

**کاربران نمونه پس از seed** (رمز همه: مقدار `SEED_ADMIN_PASSWORD` در `.env`، پیش‌فرض `Admin@1403`):

| نقش | نام کاربری | موبایل |
|---|---|---|
| مدیر کل | `superadmin` | 09120000001 |
| مدیر | `admin` | 09120000002 |
| نماینده | `reseller1` | 09120000003 |
| مشتری | — | 09120000004 |

> ⚠️ **قبل از تولید:** رمز کاربران نمونه را از پنل ادمین تغییر دهید و `SEED_ADMIN_PASSWORD` را
> برابر نگذارید.

## متغیرهای محیطی

همه‌ی متغیرها در [`.env.example`](.env.example) مستند شده‌اند. خلاصه:

| متغیر | الزامی | توضیح |
|---|---|---|
| `DATABASE_URL` | ✅ | اتصال PostgreSQL |
| `SESSION_SECRET` | ✅ | حداقل ۳۲ کاراکتر (`openssl rand -base64 48`) |
| `CRON_SECRET` | ✅ | محافظت از `/api/cron/maintenance` |
| `NEXT_PUBLIC_APP_URL` | ✅ | آدرس عمومی (برای callback درگاه) |
| `REDIS_URL` | ➖ | در صورت نبود، fallback حافظه‌ای |
| `BCRYPT_COST` | ➖ | پیش‌فرض ۱۲ |

> کلیدهای درگاه پرداخت و پیامک در **پنل ادمین → تنظیمات** ثبت می‌شوند
> (جدول `Setting` با نوع `SECRET`) و در `.env` قرار نمی‌گیرند.

## دیپلوی روی ساب‌دامین

راهنمای گام‌به‌گام «از خرید هاست تا اولین ورود به پنل»: [`docs/14-host-deployment.md`](docs/14-host-deployment.md)
مرجع معماری و تنظیمات پیشرفته: [`docs/12-deployment.md`](docs/12-deployment.md)

```bash
# روی سرور (اوبونتو ۲۲/۲۴)
git clone <repo> /var/www/simshop && cd /var/www/simshop
cp .env.example .env && nano .env          # SHOP_DOMAIN=shop.example.ir و بقیه مقادیر
docker compose up -d postgres redis

# صدور گواهی SSL
mkdir -p certbot/www certbot/conf
docker compose run --rm certbot certonly --webroot -w /var/www/certbot \
  -d shop.example.ir --email info@example.ir --agree-tos --no-eff-email

docker compose up -d --build               # اپ + nginx + بکاپ + مانیتورینگ
docker compose logs -f app                 # مایگریشن و seed خودکار
```

**DNS:** رکورد `A` برای `shop.example.ir` به IP سرور (اگر سرور ایرانی است و
CDN ندارید، Proxy را خاموش بگذارید چون درگاه ایرانی به IP سرور حساس است).

پس از بالا آمدن:

```bash
curl -fsS https://shop.example.ir/api/health      # {"ok":true,"database":"up",...}
curl -H "x-cron-secret: $CRON_SECRET" -X POST https://shop.example.ir/api/cron/maintenance
```

## تست و اعتبارسنجی

```bash
npm run typecheck            # بررسی نوع‌ها (بدون خطا)
npm test                     # ۱۰۰ تست (یونیت + کامپوننت + یکپارچه)
npm run excel:template       # ساخت و اعتبارسنجی قالب‌های اکسل
npm run build                # بیلد production

# اسموک تست HTTP روی سرور اجراشده (محلی یا روی هاست پس از دیپلوی)
npm run smoke
BASE_URL=https://shop.example.ir ADMIN_PASSWORD='...' npm run smoke
```

نتیجه‌ی اجرای واقعی در همین پروژه:

```
Test Files  14 passed (14)
Tests      100 passed (100)     ← ۸۵ یونیت + ۲ کامپوننت (jsdom) + ۱۳ یکپارچه با PostgreSQL واقعی
```

تست‌های یکپارچه موارد زیر را روی دیتابیس واقعی بررسی می‌کنند:
یکتایی شماره‌ی تکراری، **رزرو همزمان** (فقط یکی موفق می‌شود)، آزادسازی رزرو منقضی،
جلوگیری از منفی‌شدن موجودی مودم، فروش نهایی + واریز کمیسیون نماینده،
**idempotent بودن** تأیید پرداخت، و وضعیت «در انتظار ارسال فیزیکی» برای کد فعال‌سازی.
هم‌چنین **چرخه‌ی کامل پرداخت از route handler واقعی درگاه** (ساخت سفارش → `Payment INITIATED`
→ callback درگاه → verify سرور‌به‌سرور → تسویه‌ی نهایی → callback تکراری/نامعتبر).

`npm run smoke` یک لایه‌ی جداگانه است: **۲۷ بررسی واقعی HTTP** روی سرور اجراشده (سلامت
دیتابیس، RTL، هدایت مسیرهای محافظت‌شده، CSRF، ورود مدیر و نماینده، رندر هر دو داشبورد،
جداسازی نقش‌ها، خروج). این اسکریپت باگ‌هایی را می‌گیرد که فقط روی سرور دیده می‌شوند —
مثلاً حلقه‌ی ریدایرکت صفحه‌ی ورود.

## نکات بومی‌سازی ایران

- 💰 واحد پول: **تومان** (ذخیره `BigInt`، تبدیل به ریال فقط در مرز درگاه پرداخت)
- 📅 تاریخ‌ها: **شمسی** (کتابخانه `jalaali-js` + فرمت‌کننده‌های اختصاصی)
- 🔢 اعداد: **فارسی** در نمایش، پذیرش ارقام فارسی/عربی در ورودی
- 💳 درگاه پرداخت ایرانی (زرین‌پال/آیدی‌پی/نکست‌پی)
- 📱 سرویس پیامک ایرانی (کاوه‌نگار/ملی‌پیامک)
- 🚫 بدون وابستگی به CDN خارجی در زمان بیلد (فونت self-hosted)
- ⚖️ رعایت حریم خصوصی: عدم ذخیره‌ی اطلاعات کارت، ثبت رضایت در قوانین
